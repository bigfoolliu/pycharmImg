# 构建与测试命令

本文记录本项目实际使用的构建、单元测试、插件包检查和手动验证命令。以下命令均在仓库根目录执行；macOS 示例路径适用于当前 Apple Silicon 开发机。

## 1. 准备环境

```bash
# JDK 21 负责构建；build.gradle.kts 使用 --release 17 生成 Java 17 字节码。
export JAVA_HOME=/opt/homebrew/opt/openjdk@21

# 可选：直接使用本机已安装的 PyCharm 2024.1.7，避免再次下载 IDE SDK。
export PYCHARM_HOME=/Applications/PyCharm.app

# 确认仓库固定的 Gradle 版本；首次执行 Wrapper 可能下载 Gradle。
./gradlew --version
```

未设置 `PYCHARM_HOME` 时，构建脚本会下载 PyCharm 2024.1.7 作为 SDK。也可用 `-PpycharmHome=/path/to/PyCharm.app` 临时指定本机安装；Gradle 属性优先于环境变量。目标 IDE 为 `PY-241.19416.19`，与构建时使用的 JDK 版本是两回事。

## 2. 日常命令

| 命令 | 作用与检查点 |
| --- | --- |
| `./build.sh` | 自动查找 JDK 21，执行 `buildPlugin` 后用 Plugin Verifier 检查当前配置的 PyCharm SDK（当前为 2024.1.7）；不运行单元测试。ZIP 位于 `build/distributions/`，兼容性报告位于 `build/reports/pluginVerifier/`。 |
| `./gradlew help --no-daemon` | 检查 Gradle 能否加载工程配置和插件；不编译源码。 |
| `./gradlew test --no-daemon` | 编译源码与测试，运行 JUnit 4 用例；报告位于 `build/reports/tests/test/index.html`。 |
| `./gradlew buildPlugin --no-daemon` | 编译并打包插件；ZIP 位于 `build/distributions/`。 |
| `./gradlew test buildPlugin --no-daemon` | 提交前一次完成测试与打包，两个任务共用已完成的中间产物。 |
| `./gradlew runIde --no-daemon` | 启动独立 PyCharm 沙盒，检查编辑器中的悬停预览；沙盒可能单独要求激活。 |

`--no-daemon` 表示命令结束后不保留长期 Gradle 守护进程。Gradle 为匹配 JVM 参数临时启动一次性进程是正常现象。测试通过应看到 `BUILD SUCCESSFUL`，且报告中无失败用例；构建包本身不能代替编辑器中的手动验证。

## 3. 检查插件包与实际交互

```bash
# 确认打包后的版本号与 PyCharm 兼容范围；读取的是产物而非源文件。
unzip -p build/libs/pycharm-image-link-preview-0.1.1.jar META-INF/plugin.xml \
  | grep -E 'idea-version|<version>'
```

预期看到插件版本 `0.1.1`，以及 `since-build`、`until-build` 均为 `241.19416.19`。在已激活的 PyCharm 中可通过“设置 → 插件 → 齿轮菜单 → 从磁盘安装插件”选择 `build/distributions/pycharm-image-link-preview-0.1.1.zip`，按提示重启。打开含 HTTP(S) 图片链接的文本文件并悬停约 400 毫秒，确认图片显示、移开后关闭，编辑链接和切换文件后不会出现旧预览。每次改动源码后都要重新构建并安装新包。

## 4. 图片链接无法预览时

```bash
# 将地址换成需要诊断的图片链接；curl 下载响应并打印关键元数据。
IMAGE_URL='https://example.com/image.png'
curl -L -sS --max-time 30 -o /tmp/pycharmimg-check.png \
  -w 'HTTP=%{http_code} MIME=%{content_type} BYTES=%{size_download} TIME=%{time_total} REDIRECTS=%{num_redirects}\n' \
  "$IMAGE_URL"

# 检查实际文件类型与像素尺寸，不只相信 URL 后缀或服务器响应头。
file -b --mime-type /tmp/pycharmimg-check.png
sips -g pixelWidth -g pixelHeight /tmp/pycharmimg-check.png
```

插件当前只接受实际可解码的 PNG、JPEG、GIF，实际下载量最多 5 MiB，任一边最长 4096 像素，请求总时限约 5 秒。每个项目只执行一个图片请求，并仅保留最新的待处理请求；离开链接或超时时会断开连接。服务器返回通用或错误的 MIME、声明长度时，插件仍以实际图片内容和实际读取字节数判断。

## 5. 构建环境排查

若 Gradle 报找不到编译器，请确认 `JAVA_HOME` 指向完整 JDK 21，且 `"$JAVA_HOME/bin/javac" -version` 输出 21。当前机器的 PyCharm 自带 JBR 17 只有运行时，不能用作 Java 编译器。若需要重新生成 Wrapper，先安装 Gradle，再执行 `gradle :wrapper --gradle-version 9.8.1 --distribution-type bin`；生成的 `gradlew`、`gradlew.bat` 和 `gradle/wrapper/` 应一并提交。

当 Gradle 本身无法运行、但只需核对 Java 源码时，可使用下列**临时诊断**命令；它不执行 Gradle 打包或插件兼容性检查：

```bash
mkdir -p /tmp/pycharmimg-classes
find src/main/java -name '*.java' -print0 \
  | xargs -0 "$JAVA_HOME/bin/javac" --release 17 \
      -cp "$PYCHARM_HOME/Contents/lib/*" -d /tmp/pycharmimg-classes

find src/test/java -name '*.java' -print0 \
  | xargs -0 "$JAVA_HOME/bin/javac" --release 17 \
      -cp "/tmp/pycharmimg-classes:$PYCHARM_HOME/Contents/lib/junit4.jar" \
      -d /tmp/pycharmimg-classes

"$PYCHARM_HOME/Contents/jbr/Contents/Home/bin/java" -Djava.awt.headless=true \
  -cp "/tmp/pycharmimg-classes:$PYCHARM_HOME/Contents/lib/junit4.jar" \
  org.junit.runner.JUnitCore \
  dev.pycharmimg.preview.ImageLinkDetectorTest \
  dev.pycharmimg.preview.ImageLoaderTest \
  dev.pycharmimg.preview.ImageRequestExecutorTest
```

若误将生成的 `.intellijPlatform/` 目录加入 Git 暂存区，运行 `git rm --cached -r .intellijPlatform`；这只移除暂存记录，不删除本机文件。仓库的 `.gitignore` 已忽略该目录。
